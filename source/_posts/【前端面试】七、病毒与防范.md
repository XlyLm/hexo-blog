## 一、常见题

### **1. XSS 有哪几类，防御的核心思路是什么？**

存储型（恶意内容入库，他人访问时执行）、反射型（随请求参数回显）、DOM 型（前端把不可信数据写入危险位置，如 `innerHTML`、`location`、`document.write`、`eval`）。防御核心是**按输出上下文做转义**：HTML 文本转实体、属性值加引号并转义、URL 做协议白名单（禁 `javascript:`）、JS 上下文用序列化而非拼接；富文本必须走 DOM 树白名单净化（如 DOMPurify）；再叠加 CSP 与 `HttpOnly` Cookie 作为兜底。

### **2. CSRF 的原理与防御？**

用户已登录 A 站，访问恶意站点时浏览器被诱导向 A 发请求，且**自动带上 A 的 Cookie**，服务端误判为用户本人操作。防御：Cookie 用 `SameSite=Lax/Strict`（最有效的基础防线）、关键请求带 CSRF Token 并服务端校验、校验 `Origin/Referer`、敏感操作二次确认。注意 CORS 防不住 CSRF（它限制的是读取响应，不是发出请求）。

### **3. SQL 注入的原理与防御？**

把用户输入拼进 SQL 语句，使攻击者能改变查询语义（读其他表、绕过条件、甚至执行系统命令）。防御：**全部使用参数化查询/预编译**（`?` 占位符或 ORM 的绑定参数），永不字符串拼接；对输入做类型与范围校验；数据库账号最小权限；错误信息不回显 SQL 细节；WAF 作为补充而非替代。

### **4. 除了 SQL 注入，还有哪些注入类风险？**

命令注入（把输入拼进 shell，防御：不经 shell、用参数数组、白名单）、路径穿越（`../` 越出允许目录，防御：`path.resolve` 后校验前缀）、SSRF（让服务端代为请求内网地址，防御：目标白名单、禁跟随重定向、禁内网段与元数据地址）、XXE（XML 外部实体读文件，防御：禁用外部实体解析）、模板注入（用户输入被当模板执行，防御：不把输入拼进模板源码）、反序列化（不可信数据被反序列化执行，防御：不用原生反序列化处理外部输入）。

### **5. 点击劫持是什么，怎么防？**

攻击者用透明 iframe 覆盖在自己的页面上，诱导用户点击时实际点到了被嵌入的敏感页面（如转账按钮）。防御由**被嵌入方**做：`X-Frame-Options: DENY/SAMEORIGIN`，或更精确的 CSP `frame-ancestors`；配合前端检测（`window.top !== window.self` 时隐藏内容）作为补充；敏感操作加二次确认。

### **6. 文件上传有哪些风险，怎么加固？**

风险包括上传 WebShell、覆盖关键文件、路径穿越、存储型 XSS（上传 HTML/SVG 被直接访问渲染）、以及借上传接口打内网。加固：白名单校验扩展名与 MIME（不能只信 `Content-Type`）、校验文件头 magic number、重命名与随机化路径、存储到**不可执行**的目录或对象存储、按类型设置下载响应头（`Content-Disposition: attachment`、`X-Content-Type-Options: nosniff`）、限制大小与频率、图片做二次编码（剥离元数据与潜在脚本）。

### **7. 什么是越权，怎么防？**

水平越权：A 用户操作了 B 用户的数据（如改 `userId` 参数）；垂直越权：普通用户执行了管理员操作（如直接调管理接口）。防御原则是**服务端做鉴权，永不信任前端**：每个请求都要校验“当前身份 + 资源归属 + 操作权限”，用不可枚举的资源标识、最小权限的角色模型，管理接口单独网关与审计。

### **8. 敏感信息泄露有哪些常见路径？**

前端硬编码密钥（打到产物里可被直接读取）、错误响应返回堆栈与 SQL、日志打印身份证/手机号/Token、调试接口与 `/actuator` 暴露、`sourcemap` 公开、Git 目录可访问、接口返回多余字段（把内部字段一起返回）。防御：密钥只放服务端或运行时注入、统一错误响应结构、日志脱敏、生产关闭调试端点、`sourcemap` 只上传给监控平台。

### **9. 密码应该怎么存？**

绝不明文、不用 MD5/SHA1 这类快速哈希（可被彩虹表与 GPU 暴力破解）。正确做法是用**专为密码设计的慢哈希**：bcrypt、scrypt、argon2（自带盐与可调成本），存储时包含算法与参数；登录失败信息统一（不区分“用户不存在/密码错误”）、加登录限流与验证码、支持多因素认证。

### **10. 认证与会话的常见安全问题？**

Token 存 `localStorage` 会被 XSS 窃取；Session 固定攻击（登录后不换 Session ID）；JWT 的问题（`alg=none`、密钥泄露、无法即时撤销、payload 明文可读）；登出只清前端未失效服务端；密码重置流程可枚举用户。改进：`HttpOnly + Secure + SameSite` Cookie 存短期凭证、服务端维护可撤销的刷新令牌、关键操作重新鉴权、多因素认证。

### **11. HTTPS 能防什么，不能防什么？**

能防传输链路上的窃听与篡改、防中间人伪造服务端（靠证书链校验）。不能防：服务端被入侵、前端被 XSS、恶意插件/木马读取本地数据、客户端信任了伪造根证书（企业抓包）、以及应用层逻辑漏洞。因此“上了 HTTPS 就安全”是误解，它是**传输层**保障。

### **12. 常用的安全响应头有哪些？**

`Strict-Transport-Security`（HSTS，强制 HTTPS 且后续免跳转）、`Content-Security-Policy`（资源与脚本来源限制）、`X-Content-Type-Options: nosniff`（禁止 MIME 嗅探）、`Referrer-Policy`（控制来源泄露）、`Permissions-Policy`（限制摄像头/定位等能力）、`X-Frame-Options` 或 `frame-ancestors`（防点击劫持）、`Cross-Origin-Opener-Policy/Embedder-Policy`（跨源隔离）。

### **13. CSP 怎么配才有意义？**

核心是 `default-src 'self'` 收紧默认，`script-src` 用 `nonce` 或 hash 而非 `'unsafe-inline'`，`object-src 'none'`、`base-uri 'self'`、`frame-ancestors` 控制嵌入，`connect-src` 限定接口域名，`report-uri/report-to` 收集违规。务必记住 CSP 的常见绕过面：白名单里放了大 CDN（其上的 JSONP 或可控脚本）、`'unsafe-inline'`、以及 `base-uri` 未限制导致的相对路径劫持。

### **14. 依赖与供应链安全要注意什么？**

恶意包（typosquatting、抢注同名包、账号被盗后投毒）、恶意 `postinstall` 脚本、依赖混淆（内网包名与公网同名被解析到恶意版本）、以及深链依赖的已知漏洞。防御：锁定版本并提交 lockfile、私有包强制加 scope 并在源配置中优先、CI 中 `--ignore-scripts` 处理不可信依赖、定期 `npm audit`/SCA 扫描、维护 SBOM（依赖清单）以便漏洞爆发时快速定位影响范围。

### **15. 限流与防刷怎么设计？**

按维度限流（IP、用户、接口、设备指纹），用令牌桶/滑动窗口，超限返回 `429` 并带 `Retry-After`；关键业务（登录、注册、短信、支付）加验证码与行为校验；风控要“分级处置”（先验证码、再限流、最后封禁），避免误伤与硬封锁。前端限流只是体验优化，真正的防线在服务端与网关。

### **16. 恶意软件主要有哪些类型？**

病毒（依附文件、需宿主传播）、蠕虫（自我复制、主动扫描传播，如永恒之蓝类蠕虫）、木马（伪装正常程序、开后门窃密）、勒索软件（加密文件索要赎金）、间谍软件（窃取键盘/屏幕/凭据）、广告软件、Rootkit（隐藏自身在内核或固件层）、僵尸网络（受控肉鸡发起 DDoS）、挖矿木马、以及“无文件攻击”（只在内存与脚本层活动，落盘痕迹少）。

### **17. 恶意软件的常见传播途径有哪些？**

钓鱼邮件与附件、伪装成常用软件的下载站（水坑攻击）、漏洞利用（未打补丁的浏览器/插件/远程服务）、U 盘与移动介质、供应链投毒（软件更新包、第三方库、开源组件）、社会工程（假客服、假 IT 支持、诱导装“远程协助”工具）、以及弱口令爆破后植入。

### **18. 勒索软件怎么防，被加密后怎么办？**

防：离线/不可变备份（3-2-1 原则，至少一份离线或只读）、及时打补丁、最小权限与禁用不必要的共享、开启 EDR 行为拦截、邮件附件与宏禁用、员工演练。被加密后：**立即隔离断网**（防止横向扩散）、保留现场取证、从离线备份恢复、不要轻易支付赎金（不保证解密且资助犯罪），并向监管与安全团队上报。

### **19. 杀毒软件是怎么工作的？**

三类检测：特征码匹配（比对已知恶意代码片段，快但滞后）、启发式/静态分析（看可疑结构与权限请求）、行为监控（运行时检测异常行为链，如“加密大量文件 + 删除影子副本”）。现代终端防护演进为 EDR：持续采集进程、网络、文件行为，做关联分析与响应（隔离主机、终止进程、回滚）。**特征码对 0day 与变形恶意代码无能为力**，这正是行为检测存在的理由。

### **20. 钓鱼攻击怎么识别和防范？**

识别：发件域名与显示名不一致（形近字符）、紧急与恐吓话术、要求开启宏或输入密码、附件是 `.html/.iso/.lnk` 等异常类型、链接与显示文本不符（悬停看真实域名）。防范：邮件网关做 SPF/DKIM/DMARC 校验与附件沙箱、双因素认证（防凭据被钓后直接登录）、定期钓鱼演练、建立“可疑邮件上报通道”。

### **21. 什么是纵深防御与最小权限？**

纵深防御：不依赖单点防护，在网络、主机、应用、数据、人员多个层面叠加（WAF + 鉴权 + 参数校验 + 加密 + 审计 + 备份），任何一层被突破仍有下一层。最小权限：账号、服务、容器、数据库都只授予完成任务所需的最小范围，配合权限分离（开发不能直接改生产库）与临时提权审批。二者共同降低“单点失守导致全面失陷”的概率。

### **22. 安全事件应急响应的流程是什么？**

六阶段：准备（预案、联系人、工具与权限）→ 检测与分析（确认是否真实事件、影响范围）→ 抑制（先止血：断网、隔离主机、封禁账号、下线接口）→ 根除（清除恶意代码、修补漏洞、重置凭据）→ 恢复（从可信备份恢复、灰度验证、加强监控）→ 总结（复盘时间线、补控制措施、更新预案）。原则是“先抑制再根除”，且全程保留证据链，避免破坏取证。

## 2、难题

### **1. 为什么 XSS 防御不能靠关键字黑名单？**

危险上下文太多（HTML 文本、属性、URL、JS 字符串、CSS、SVG），绕过手法无穷（编码、大小写、注释截断、`javascript:` 伪协议、事件属性、`<template>` 嵌套、mXSS——浏览器解析与净化器解析不一致）。黑名单必然会漏。正确路径是“**按上下文白名单转义** + DOM 树净化 + CSP 兜底”，并且净化要在**解析后**的 DOM 上进行，而不是对字符串做正则。

### **2. CSP 严格模式下还有哪些绕过面？**

白名单中的大站 CDN（能上传 JSONP 或可控脚本）、`script-src` 里放了 `'unsafe-inline'` 或 `data:`、`base-uri` 未限制（攻击者注入 `<base>` 劫持相对路径脚本）、`frame-src` 宽松导致 iframe 内脚本执行、以及 `nonce` 被复用（把 nonce 写在可被读取的 DOM 上）。所以严格 CSP 需要同时收紧 `object-src`、`base-uri`、`form-action`，并避免给 CDN 白名单开放上传能力。

### **3. SSRF 防御为什么难，怎么做得更稳？**

难点在于校验与请求之间存在时间差（DNS rebinding：先解析到公网、校验通过后重解析到内网），以及重定向、IPv6/十进制 IP、云元数据地址（`169.254.169.254`）、协议多样性（`file://`、`gopher://`）。稳妥做法：目标用**白名单域名**而非黑名单 IP、在建立连接时校验实际解析出的 IP（解析与连接用同一个结果）、禁用重定向跟随、禁用非 HTTP 协议、网络层做出口限制（代理只允许访问必要域名）。

### **4. 供应链攻击为什么难以防御？**

因为信任是传递的：你用 100 个直接依赖，实际可能引入上千个间接依赖，其中任何一个维护者账号被盗、包被投毒、或版本被撤回替换，都会进入你的构建。防御要点是“**减少信任面 + 可追溯**”：lockfile 锁死并校验完整性哈希、私有源代理并缓存（禁止直连公网）、CI 禁跑安装脚本、SCA/SBOM 持续扫描、对关键依赖做版本冻结与人工评审、发布使用 provenance 与 2FA。

### **5. 特征码检测为什么对高级恶意软件效果有限？**

因为攻击者可以轻易改变字节特征（加壳、多态、混淆、无文件落地），每次变种都逃过旧特征；特征库更新永远滞后于 0day。现代方案转向**行为与上下文**：监控进程树异常（Office 拉起 PowerShell）、敏感操作序列（批量改写文件 + 删除卷影副本）、以及信誉与网络外联，再结合机器学习与沙箱动态分析。代价是误报率上升，需要白名单与人工研判配合。

### **6. 勒索软件为什么经常连备份一起加密，怎么避免？**

因为勒索团伙会先做**横向移动与权限提升**，拿到备份服务器或域管凭据，再删除卷影副本（`vssadmin delete shadows`）并加密网络共享。因此备份必须“**与生产环境解耦**”：离线/磁带/只读介质、独立账号与网络分区、备份服务器不允许来自生产网的写权限、定期做**恢复演练**（没验证过的备份等于没有备份）。

### **7. 应急响应中“抑制”与“取证”如何平衡？**

抑制（断网、关机、封禁）能快速止血，但会破坏内存中的证据（进程、网络连接、恶意代码样本）。平衡做法是：先做**易失性证据采集**（内存镜像、进程列表、网络连接、登录日志），再执行抑制；对关键主机优先“网络隔离但不关机”（保留内存）；全程记录操作时间线与操作人。事后复盘要把“取证优先”的步骤写进预案，否则每次都靠临场判断。

### **8. 补丁管理与 0day 窗口怎么应对？**

现实是“无法全部及时打补丁”，所以要分层：资产清单与版本可视化（不知道有什么就打不了补丁）、按暴露面分级（公网服务优先）、虚拟补丁（WAF/IPS 规则先挡已知利用方式）、临时缓解（关闭不必要的服务与端口、收敛权限）、以及针对 0day 期间的**加强监控**（异常外联、异常进程）。补丁窗口的收益取决于“暴露时间 × 资产数量”，而不是“打了多少补丁”。

# 一、HTML

## 1、常见题答案

### **1. HTML5 新特性的分类答案**

H5 新增了语义化标签、多媒体（`video/audio`）、Canvas、SVG、本地存储、表单增强（`type=email/date/number`）、拖拽、WebWorker、WebSockets、地理定位等能力，丰富网页表现与交互。

### **2. H5语义化**

HTML语义化是指**根据内容的含义（语义）来选择合适的HTML标签**，而不是仅仅为了视觉效果而滥用 `<div>` 和 `<span>`。

- **可访问性（无障碍）**：屏幕阅读器能理解页面结构，视障用户能更好地导航。
- **SEO**：搜索引擎能更准确理解内容结构和重要性。
- **可维护性**：代码可读性强，团队协作和后期维护更容易。
- **设备兼容**：利于阅读模式、爬虫、浏览器插件等正确解析。

### **3. `DOCTYPE` 的作用**

DOCTYPE声明文档类型用来告知浏览器文档类型，开启标准模式；标准模式按W3C规范渲染，混杂模式为兼容旧浏览器按浏览器自有怪异规则渲染。

**标准模式（Standards Mode）**

- 有正确 `<!DOCTYPE>`，**严格遵循 W3C 规范渲染**
- 盒模型：`width/height` 只代表**内容区**，padding、border 向外叠加（`content-box`）MDN Web Do...
- 行内元素（span）设置宽高无效
- 父元素没固定高度时，子元素百分比 height 不生效
- `margin:0 auto` 可以正常实现块级水平居中
- 图片按基线对齐，图片底部会出现默认间隙
- overflow 溢出内容默认裁剪

**混杂模式 / 怪异模式（Quirks Mode）**

- 缺少或写错 DOCTYPE，**模拟 IE5.5 旧浏览器渲染**，兼容古老页面MDN Web Do...
- 盒模型：`width/height` 包含 content + padding + border（`border-box`）MDN Web Do...
- 行内元素可以设置宽高
- 父元素无高度，子元素百分比 height 可能生效
- `margin:0 auto` 居中失效，一般靠 `text-align:center`
- 图片对齐到盒子底边，底部没有基线间隙
- table 字体样式不继承父级；溢出时盒子会撑开包住内容

### **4. 元素分类**

块元素独占一行、可设置宽高；行内元素同行排列、宽高由内容决定，不能直接设置宽高。

### **5. `src` 与 `href`**

`src` 用于替换元素（`img/script/iframe/video`），资源的加载会阻塞该元素的解析与渲染，因此它是“内容来源”；`href` 建立引用关系（`a/link`），浏览器并行处理，`link` 加载样式会阻塞渲染但不阻塞 HTML 解析。**追问**：`script` 的 `src` 是解析阻塞的，除非加 `defer/async`。

### **6. `defer` 与 `async`**

两者都只对外部脚本生效、都不阻塞 HTML 解析。`defer` 推迟到解析完成、`DOMContentLoaded` 之前，按文档顺序执行；`async` 下载完成即执行，顺序不确定。选择依据是依赖关系：需要访问 DOM 或脚本之间有依赖用 `defer`；互不依赖的统计、监控脚本用 `async`，避免拖慢关键路径。**追问**：内联脚本加这两个属性无效；两者同时存在时 `async` 优先。

### **7. `meta` 的常用配置**

`charset="utf-8"` 必须放在 `head` 最前面，否则编码嗅探可能已按错误编码开始解析；`viewport` 的 `width=device-width, initial-scale=1` 决定移动端的 CSS 像素映射，加上 `viewport-fit=cover` 才能使用安全区变量；`description` 影响搜索结果摘要；Open Graph（`og:title/og:image`）决定社交平台分享卡片的呈现；`http-equiv` 可做兼容性设置与自动刷新（后者在业务页面应避免）。

### **8. 前端 SEO 的清单**

基础项：唯一且准确的 `title` 与 `description`、语义化结构、合理的 URL 层级与内链；技术项：`canonical` 去重、`robots.txt` 与 `sitemap.xml`、JSON-LD 结构化数据、首屏内容可被抓取（SSR、预渲染或至少首屏直出）、避免关键内容完全依赖 JS 异步渲染；体验项：移动端友好、体积与 LCP 达标（页面体验也是排名因素）。**追问**：纯前端 SPA 为什么不利于 SEO，答案要落到“抓取时可能拿不到渲染后的内容”。

### **9. `disabled`、`readonly`、`hidden`**

`disabled`：不可交互、不可聚焦、**不参与表单提交**，`form` 提交时被忽略；`readonly`：不可编辑但可聚焦、可选中、**会提交**，适用于文本类输入与 `textarea`（对 `select/checkbox` 无效）；`hidden`：仅不渲染，值照常提交。业务上“提交前暂时锁住但仍需要值”应该用 `readonly` 而非 `disabled`，这是实际踩坑点。

### **10. `data-\*` 与 `dataset`**

`data-user-id` 在 `dataset` 中映射为 `userId`（连字符转驼峰，且只对 ASCII 小写有效），值永远是字符串，取数字要转类型；写 `dataset` 会同步回 attribute。适合承载小的业务标识（行 id、状态），不适合放大段 JSON（可读性差、每次序列化有开销，且会被暴露在 HTML 中）。**追问**：React 中 `data-*` 直接写属性即可，`dataset` 操作会绕过框架的更新机制。

### **11. `alt` 的三类写法**

内容图：描述图片传达的信息，而不是“一张图片”；装饰图：`alt=""`，让辅助技术直接跳过；功能图：写功能或动作（如“搜索”“返回”），而不是外观。区分“缺失 `alt`”与“`alt=""`”是关键：前者会让阅读器朗读文件名，后者表示有意忽略。**追问**：`img` 必须配 `alt` 属性（哪怕为空），这是 WCAG 的硬性要求。

### **12. 原生表单校验**

声明式约束：`required`、`pattern`、`min/max/step`、`minlength/maxlength`、`type` 自带格式校验。编程式：`checkValidity()` 返回布尔值且不弹提示，`reportValidity()` 会触发浏览器气泡，`setCustomValidity(msg)` 设置自定义错误（必须在下次校验前清空，否则会一直无效），`validity` 对象可细分 `valueMissing`、`patternMismatch`、`typeMismatch` 等。**追问**：样式上可用 `:invalid`、`:user-invalid` 控制提示时机，后者只在用户交互后才匹配，体验更好。

### **13. `label` 的作用**

`for` 与控件的 `id` 绑定后，点击文字即可聚焦或切换控件，触屏上把可点击区域扩大；屏幕阅读器通过关联朗读说明；对 `checkbox/radio` 尤其重要，否则小圆点极难点中。**追问**：把控件包在 `label` 内也能关联，但一个 `label` 只能关联一个控件，多个控件会只认第一个。

### **14. `contenteditable` 的坑**

浏览器会生成不可控的 HTML（不同浏览器插入的标签、换行方式都不同）、粘贴会带内联样式与脚本、光标与选区需要用 `Range/Selection` 手工管理、输入法组合期（`compositionstart` 到 `compositionend`）处理不当会丢字或重复、撤销栈不可控。工程做法是用成熟编辑器内核（自研成本极高），并在输入时做 HTML 白名单净化。

## 2、难题答案

**1. 容错解析的具体例子**

HTML5 定义了完整的解析算法：分词阶段做字符到 token 的转换，树构建阶段按“插入模式（insertion mode）”决定 token 插到哪。表格有专门的插入模式，非表格内容会被移到表格之外；`<p>` 遇到块级开始标签会自动闭合（所以 `p` 不能套 `div`）；格式化标签（`b/i/a`）交错嵌套时触发“重新分配格式化元素”的算法，把树纠正成合法结构。结论：浏览器不会因为标签问题报错，而是按规范“猜测意图”，因此同一份错误 HTML 在不同引擎下结果一致，但开发者看到的 DOM 与源码可能完全不同。**追问**：这解释了为什么 XSS 过滤要基于解析后的 DOM 而不是正则匹配字符串。

**2. attribute 与 property 的差异**

attribute 是 HTML 里写的字符串，property 是 DOM 对象上的实时值。绝大多数会双向映射，但表单状态类属性有“脏值标志”：用户交互改变 `value/checked/selected` 后，attribute 停在初始值，`getAttribute('value')` 返回的仍是原来的字符串，而 `.value` 返回当前值。因此读表单状态一律用 property；`setAttribute('value', x)` 只能改默认值，改不了用户已输入的内容（除非用 `.value`）。另外 `class` 对应 `className`、`style` 是解析后的 CSSStyleDeclaration、`href` 的 property 是绝对 URL 而 attribute 是原始字符串。**追问**：这也是 React 受控组件要求“值从 state 来”的底层原因。

**3. 为什么写 `width`/`height` 能减小 CLS（累积布局偏移）**

图片未加载时浏览器不知道尺寸，只能按 0 高度排版，图片到达后把下方内容全部推开，产生布局偏移。写上 `width` 与 `height` 属性后，浏览器据此算出内在宽高比，在下载前就预留正确比例的空间；配合 CSS 的 `max-width: 100%` 与 `height: auto`（或 `aspect-ratio`），缩放时仍按比例，于是预留尺寸与实际尺寸一致，偏移消失。**追问**：`aspect-ratio` 适合容器自适应场景，但它要求比例写对，否则预留与实际不符反而更糟。

**4. `srcset`/`sizes` 的匹配算法**

`srcset` 的 `x` 描述符直接表达 DPR（`logo@2x.png 2x`）；`w` 描述符表达资源像素宽度，此时必须配 `sizes`，浏览器先按 `sizes` 计算该图在布局中的 CSS 宽度，乘以当前 DPR 得到“需要的像素数”，再从候选里选不小于该值的最近资源。写错 `sizes` 是最常见的错误（例如布局实际 480px 宽却写 `sizes="100vw"`），会导致高分屏取到过大的图、低带宽取到过大的体积。**追问**：还需要配合 `loading="lazy"` 与首屏图的 `fetchpriority="high"` 才能兼顾首屏体验。

**5. `iframe` 的代价与隔离**

代价：独立渲染进程或上下文、额外的内存与网络开销、受限于同源策略无法读取内容、会推迟父页面的 `load` 事件；多个 iframe 会显著拖慢首屏。隔离：`sandbox` 属性默认禁用一切（脚本、表单、同源），需要按需放开 `allow-scripts/allow-forms/allow-popups`，注意**同时放开 `allow-scripts` 与 `allow-same-origin` 等于让内嵌页面获得与父页面同源的脚本能力，沙箱形同虚设**；`allow`（权限策略）限制摄像头、麦克风、定位；`referrerpolicy` 控制来源泄露；防点击劫持用 `X-Frame-Options` 或 CSP 的 `frame-ancestors`。跨域通信只能 `postMessage`，接收端**必须校验 `event.origin` 且不信任消息内容**。**追问**：微前端用 iframe 做隔离的代价就是这些通信与体验（弹层、路由、焦点）问题。

**6. `<template>`、`inert`、`content-visibility` 的分工**

`<template>` 的内容是“惰性的”：不在文档树中渲染、内部资源不加载、脚本不执行，直到被 JS 克隆插入，因此是框架与 Web Components 的标准容器。`inert` 让整棵子树不可聚焦、不可点击、不可被查找、对辅助技术隐藏，是弹窗打开时处理背景的最正确做法（比遮罩加逐个禁用可靠）。`content-visibility: auto` 让视口外的子树跳过样式与布局计算，必须配 `contain-intrinsic-size` 给出预估高度，否则滚动条长度会跳动。**追问**：三者都不改变 DOM 结构，区别在“何时渲染、是否可交互”。

**7. Web Components 的生命周期**

`constructor` 只做初始化，不要访问属性或子节点（此时还没有）；`connectedCallback` 在插入文档时调用，适合绑定事件与启动逻辑；`attributeChangedCallback` 只在 `observedAttributes` 中声明的属性变化时触发；`disconnectedCallback` 必须清理定时器、监听与请求，否则会泄漏；`adoptedCallback` 在跨文档移动时触发。Shadow DOM 用 `attachShadow({mode:'open'})` 创建，`<slot>` 承载外部传入的内容，样式默认隔离；SSR 可用声明式 Shadow DOM（`<template shadowrootmode="open">`）直出，但需要浏览器支持与降级方案。**追问**：`mode: 'closed'` 时外部无法访问内部节点，调试与测试会变难。

**8. 编码嗅探与 `document.write`**

编码判定顺序大致为：BOM、HTTP 响应头 `Content-Type`、`<meta charset>`、父文档继承、浏览器猜测。因此 `meta charset` 必须出现在文档前 1024 字节内，否则浏览器已按错误编码开始解析，后面再声明也来不及，表现为中文乱码。`document.write` 在解析阶段会把内容插入当前位置并阻塞解析；在异步脚本、`defer` 脚本或文档已关闭后调用会触发隐式 `document.open()`，**清空整个文档**，这就是老广告 SDK 导致整页白屏的机制。**追问**：现代替代方案是 DOM API 插入节点或 `insertAdjacentHTML`。

# 二、CSS

## 2、常见题

### **1. 标准盒模型和 IE 盒模型有什么区别？`box-sizing` 干什么用？**

标准盒模型 `width` 只含内容区，占位 = width + padding + border + margin；IE 盒模型 `width` 已含 padding 与 border。`box-sizing: border-box` 让宽度包含内边距与边框，是组件开发默认；注意它是**可继承属性**，全局设置后老组件可能变形，需要局部还原。

### **2. 水平垂直居中至少说四种方式。**

Flex：父级 `display:flex; justify-content:center; align-items:center`；Grid：父级 `display:grid; place-items:center`；绝对定位 + `transform: translate(-50%,-50%)`（不需要知道尺寸）；绝对定位 + `inset: 0; margin: auto`（需固定宽高）；老方案 `table-cell` + `vertical-align`。**追问**：元素有固定宽高时负 margin 更稳，无宽高时只能靠 transform。

### **3. BFC 是什么，怎么触发，解决什么问题？**

块级格式化上下文，一块独立渲染区域。触发：根元素、`float` 非 none、`position` 为 absolute/fixed、`display` 为 inline-block/table-cell/flow-root/flex 或 grid 子项、`overflow` 非 visible。四项作用：包含内部浮动、阻止父子外边距合并、避免被浮动元素覆盖（自适应两栏）、隔离内外布局。最轻量写法 `display: flow-root`，避免 overflow 的裁剪副作用。

### **4. 清除浮动有哪几种方式？**

`clear: both`（在浮动后加元素）、父级触发 BFC（`flow-root`/`overflow:hidden`）、伪元素 `::after{content:'';display:table;clear:both}`、现代方案直接改用 Flex/Grid（浮动不再参与布局）。**追问**：为什么要清浮动——浮动元素脱离常规流，父容器高度计算忽略它们，导致高度塌陷。

### **5. 什么是外边距合并（margin 塌陷）？怎么解决？**

相邻兄弟、父子（父无 border/padding 且非 BFC）、空块自身三种情形下，相邻外边距合并为较大者（负值时取更负）。解决：父级触发 BFC、加 padding 或 border、改用 `gap` 或 Flex 布局。浮动与绝对定位元素不参与合并。

### **6. 层叠与优先级怎么算？**

顺序是：来源与重要性（用户代理/作者/用户，`!important` 反转）→ 权重 → 声明先后。权重写成四元组（行内, ID, 类/属性/伪类, 元素/伪元素），**逐位比较不做进位**，所以 11 个类也压不过 1 个 ID。`!important` 高于普通声明，但用户样式的 `!important` 仍高于作者样式。

### **7. `z-index` 设很大却不生效，为什么？**

因为它只在**同一层叠上下文**内比较。父级若创建了层叠上下文（`position` + 非 auto 的 z-index、`transform`、`filter`、`opacity<1`、`will-change`、`isolation:isolate`、`contain`、Flex/Grid 子项带 z-index），子元素就被锁在该上下文内，无法越过外部兄弟。排查方式是沿祖先链找谁创建了上下文，而不是继续加大数字。

### **8. 说一下层叠上下文与绘制顺序。**

上下文内从下到上：上下文背景与边框 → 负 z-index 子上下文 → 块级盒子 → 浮动 → 行内 → z-index 为 0/auto 的定位元素 → 正 z-index 子上下文。这就是“某些浮层总被盖住”的原因。

### **9. Flex 里 `flex: 1` 和 `flex: auto` 有什么区别？**

`flex` 是 grow/shrink/basis 的简写：`flex:1` = `1 1 0%`，基准为 0，各项等分剩余空间；`flex:auto` = `1 1 auto`，先保留内容宽度再分剩余，结果不等分；`flex:none` = `0 0 auto`。**追问**：`flex` 子项 `min-width` 默认 auto，长文本不收缩，要显式 `min-width: 0`。

### **10. `justify-content` 和 `align-items` 分别作用在哪条轴？**

主轴由 `flex-direction` 决定：`justify-content` 控主轴分布，`align-items` 控交叉轴对齐；`align-content` 只在多行（`flex-wrap: wrap`）时生效，这是最常见的混淆点。

### **11. Flex 和 Grid 怎么选？**

Grid 是二维（行列同时控制），适合整体布局、卡片自适应（`repeat(auto-fill, minmax(220px,1fr))`）；Flex 是一维，适合线性排列与不确定项数。`auto-fill` 保留空轨道（少项时左对齐），`auto-fit` 折叠空轨道（少项时铺满），这是常见考点。

### **12. 实现左右固定、中间自适应。**

Flex：两侧 `flex: 0 0 200px`，中间 `flex: 1 1 0%; min-width: 0`；Grid：`grid-template-columns: 200px 1fr 200px`；绝对定位：中间左右留空；浮动 + BFC：中间触发 BFC 自动避让。经典圣杯/双飞翼用负 margin 加 padding 实现，现在只需会说原理。

### **13. 移动端适配有哪些方案？**

vw 方案（`postcss-px-to-viewport` 把 px 转 vw，等比缩放、无运行时开销，主流）；rem 方案（早期 `flexible` 动态根字号，现已不推荐），现在多用固定根字号加少量 rem；媒体查询按断点切布局；容器查询 `@container` 做组件级自适应。限制：大屏需 `max-width` 兜底，字体是否缩放按产品要求定。

### **14. 移动端 1px 变粗怎么解决？**

原因：设计稿的 1px 是物理像素，DPR=2/3 时 CSS 1px 会渲染成 2~3 个物理像素。方案：伪元素 + `transform: scaleY(0.5)`（兼容最好）、`box-shadow` 内阴影、直接写 `0.5px`（部分安卓不支持）、`border-image` 渐变。工程上用构建插件按 DPR 自动处理。

### **15. 重排和重绘的区别，怎么减少？**

重排是几何属性变化导致布局重算（宽高、位置、字体、增删节点），必然伴随重绘；重绘只重画外观（颜色、背景、阴影）。减少手段：批量改样式（切 class）、离线操作（先 `display:none`）、动画用 `transform`/`opacity` 走合成层、读写分离避免强制同步布局、用 `requestAnimationFrame` 合并帧内更新。

### **16. `display:none`、`visibility:hidden`、`opacity:0` 有什么区别？**

`display:none` 不进渲染树、不占位、不参与布局，无法过渡动画；`visibility:hidden` 保留占位、不可交互、可被子元素 `visible` 覆盖、可过渡；`opacity:0` 保留占位、**仍可点击**（需配 `pointer-events:none`）、可过渡、可能创建层叠上下文。

### **17. `position` 五个值分别什么含义？**

`static` 默认、不参与定位；`relative` 相对自身原位置偏移、保留占位、可作为定位参照；`absolute` 相对最近的非 static 祖先（否则初始包含块）定位、脱离文档流；`fixed` 相对视口（祖先有 transform/filter 时改为相对该祖先）；`sticky` 在滚动到阈值前表现为 relative、之后吸附，需设置 `top/bottom` 才有意义。

### **18. 伪类和伪元素有什么区别？**

伪类描述状态或结构（`:hover`、`:focus`、`:nth-child`、`:has`），伪元素创建文档中不存在的元素（`::before`、`::after`、`::placeholder`）。遵守单冒号/双冒号区分；`::before/::after` 必须写 `content` 才生效，且不能承载可交互内容（无障碍不可见）。

### **19. `link` 引入和 `@import` 有什么区别？**

`link` 是 HTML 标签、并行加载、可被 JS 动态控制、无兼容问题；`@import` 是 CSS 语法、串行加载（前一个样式表解析到该行才发起请求）、必须写在文件顶部、无法被条件加载。工程上一律用 `link` 或构建工具注入。

### **20. `px`、`em`、`rem`、`%`、`vw` 有什么不同？**

`px` 是 CSS 逻辑像素（受 DPR 影响）；`em` 相对**当前元素**字号（用于 `font-size` 时相对父级，容易层层放大）；`rem` 相对根字号，最稳定；`%` 的参照随属性变化——宽、`padding`、`margin` 都参照包含块**宽度**，`height` 参照包含块高度（父高 auto 时失效）；`vw/vh` 相对视口。

### **21. 手写：一个三角形怎么做？**

宽高为 0，用边框构造：`border-left/right: 50px solid transparent; border-bottom: 100px solid #000`。原理是相邻边框以 45° 斜接，把其他三边设为透明就只剩一个三角。**追问**：如何做右指三角形——调换透明与非透明边的位置即可。

### **22. 手写：单行与多行文本溢出省略。**

单行三件套：`overflow:hidden; text-overflow:ellipsis; white-space:nowrap`。多行用 `-webkit-line-clamp`：`display:-webkit-box; -webkit-box-orient:vertical; -webkit-line-clamp:3; overflow:hidden`（非标准但有广泛支持），或 CSS 新属性 `line-clamp` 配合 `block-ellipsis`（支持度有限）。

## 2、难题

### **1. `min-width:auto` 为什么让 Flex 收缩失效？**

Flex 子项的最小尺寸默认取 `auto`，语义是“不小于内容的最小尺寸”，因此长单词或无断点文本会阻止收缩，表现为“设了 `flex:1` 仍溢出”。解法是显式 `min-width:0`（或 `overflow:hidden`），并在文本上配 `overflow-wrap:anywhere`。这是可把容器自适应与文本换行两个知识点串起来的题。

### **2. `position: sticky` 失效的常见原因？**

四条：一是没有一个方向的偏移值（`top/left` 等未设）；二是最近的滚动祖先的 `overflow` 不是 visible（会改变粘附容器，常见于 `overflow:hidden` 的父级）；三是父级高度不足，元素没有滚动空间可“粘”；四是祖先有 `transform/filter/perspective` 时会创建新包含块，粘附参照被改。排查方式是逐级检查祖先的 overflow 与 transform。

### **3. `fr` 与百分比混用为什么会溢出？**

`fr` 分配的是**扣除固定轨道与 `gap` 之后的剩余空间**，而百分比按容器总宽度计算；两者混用会导致总额超过 100%。正解是用 `minmax(0, 1fr)` 明确最小值为 0（默认的最小值 auto 也可能让内容撑破轨道），这同时解决“Grid 中长文本撑破列”的问题。

**4. `will-change` 与合成层的代价是什么？

`will-change: transform` 会提前把元素提升为独立合成层，动画时跳过布局与绘制，代价是显存占用与纹理上传；层数过多会造成内存暴涨与合成开销上升。正确用法是动画开始前设置、结束后移除，或用 `transform` 的 `translateZ(0)` 同理但同样要节制。

### **5. `margin` 的百分比为什么按宽度算，垂直方向也是？**

CSS 规范中 `margin/padding` 的百分比一律参照**包含块的内联尺寸（宽度）**，垂直方向同样如此，以保证块级布局的“宽度循环”不被打破。这带来一个实用技巧：`padding-top: 66.67%` 可以做 16:9 等比容器，但更推荐用 `aspect-ratio`。

### **6. CSS 变量与预处理器变量有什么区别？**

CSS 变量是运行时值，参与继承、可被 JS 读写、支持动态主题切换，但无法做颜色函数运算（可配合 `color-mix`）；Less/Sass 变量在编译期替换成字面量，可做运算与混入，但换主题需要重新构建。进阶点是 `@property`：声明变量的类型、初始值与继承性后，可让变量参与过渡与动画（否则 `transition` 对变量无效）。

### **7. 层叠层 `@layer` 改变了什么？**

它提供了比“权重”更直接的顺序控制：未分层样式的优先级高于分层样式，层内按声明顺序，层的顺序由首次声明决定。价值是引入第三方样式后仍能稳定覆写，不必靠 `!important` 堆权重；代价是团队要约定层顺序，否则调试时不容易判断优先级来源。

### **8. 移动端为什么 `100vh` 会有问题？**

浏览器工具栏收放会改变可视高度，`vh` 按“最大视口”计算，导致底部内容被遮挡。解法是用新单位 `dvh`（动态视口）、`svh`（最小）、`lvh`（最大），或用 `calc(var(--vh, 1vh) * 100)` 配合 `resize` 监听兜底；配合 `env(safe-area-inset-bottom)` 处理刘海屏与底部横条。

# 三、JS

## 1、常见题

### **1. JS 有哪些数据类型，怎么判断？**

基础类型七种：`undefined`、`null`、`boolean`、`number`、`string`、`symbol`、`bigint`；引用类型为 `object`（含数组、函数、日期、正则、Map、Set）。判断方式：`typeof` 能安全处理未声明变量，但把 `null`、数组、日期都判成 `object`；`instanceof` 依赖原型链、跨 Realm 失效；`Object.prototype.toString.call()` 最通用；数组用 `Array.isArray`；判断 `NaN` 用 `Number.isNaN`（`Object.is` 更严格）。

### **2. `var`、`let`、`const` 有什么区别？**

`var` 函数作用域、声明提升且初始化为 `undefined`、可重复声明、会成为全局对象属性；`let/const` 块级作用域、存在暂时性死区（声明前访问抛 `ReferenceError`）、不可重复声明；`const` 只保证绑定不可重新赋值，对象内部仍可变。循环中用 `let` 每次迭代创建新绑定，是闭包经典题的解法。

### **3. 什么是闭包，有什么用，会内存泄漏吗？**

函数与其定义时词法环境的组合。用途：私有变量、函数工厂、缓存（记忆化）、防抖节流、模块模式、Hooks 中跨渲染保存状态。闭包本身不造成泄漏，只有当长生命周期的引用（全局事件、定时器、未取消的订阅）持有闭包、闭包又持有大对象时才表现为泄漏；解绑、清理定时器即可回收。

### **4. 说说原型链，`instanceof` 怎么实现？**

函数有 `prototype`，实例的 `__proto__` 指向它，逐级向上到 `Object.prototype` 再到 `null`；属性查找沿链进行。`instanceof` 取右侧的 `prototype`，沿左侧对象的原型链逐级比对，命中返回 `true`；局限是跨 iframe/Realm 误判、基础类型返回 `false`。

### **5. 继承有哪几种实现？**

原型链继承（共享引用类型，有副作用）→ 构造函数继承（无法继承原型方法）→ 组合继承（调用两次构造函数）→ 寄生组合继承（`Object.create` 复制原型，只调一次）→ `class`。`class` 是语法糖，但不会被提升、必须用 `new`、方法不可枚举且默认严格模式。

### **6. `this` 的绑定规则有哪些？**

优先级：`new` 绑定 > 显式绑定（`call/apply/bind`）> 隐式绑定（`obj.fn()`）> 默认绑定（严格模式 `undefined`，非严格模式全局对象）。隐式绑定丢失的三种场景：方法赋给变量、作为回调传入、放进 `setTimeout`。箭头函数没有自己的 `this`，取定义时外层值，无法被 `call` 改变。

### **7. `new` 操作符做了什么？**

四步：创建空对象 → 把它的原型指向构造函数的 `prototype` → 以它为 `this` 执行构造函数 → 构造函数返回对象则用该对象，否则返回第一步创建的对象（非对象返回值被忽略）。

### **8. `call`、`apply`、`bind` 有什么区别？**

`call` 与 `apply` 立即执行，区别只在参数形式（逐个 vs 数组）；`bind` 返回绑定了 `this` 与部分参数的新函数，不立即执行，且用 `new` 调用时绑定的 `this` 会被忽略（需要手写兼容）。

### **9. 讲一下事件循环。**

任务分宏任务（整体脚本、`setTimeout`、`setInterval`、`MessageChannel`、I/O 回调）与微任务（`Promise.then`、`queueMicrotask`、`MutationObserver`、`await` 之后的续体）。每轮取一个宏任务执行，执行完**清空整个微任务队列**（清空过程中新产生的也一并执行），然后判断是否需要渲染（`requestAnimationFrame` 回调、样式计算、布局、绘制、合成），再进入下一轮。结论：微任务会阻塞渲染；`setTimeout` 有最小延迟，嵌套超过五层后不低于 4ms。

### **10. 输出题怎么分析（同步 + Promise + setTimeout 混排）？**

三步：标出同步代码 → 把回调按宏/微排队 → 按“同步跑完、清空微任务、取下一个宏任务、再清空微任务”的顺序推演。要点是 `await` 之后的代码等价于 `then` 回调（进微任务），`resolve` 一个 thenable 会多消耗一个微任务周期，`then` 里 return 的值决定下一个链的状态。

### **11. Promise 的状态与 `then` 返回值规则？**

三态且不可逆（pending → fulfilled/rejected）。`then` 总返回新 Promise：回调返回普通值则兑现、返回 Promise 则等待其敲定、抛出异常则拒绝；未传拒绝处理时，拒绝会沿链传递（错误穿透）。构造阶段的同步异常会让 Promise 直接拒绝而非抛出。

### **12. `all`、`allSettled`、`any`、`race` 有什么区别？**

`all` 全部成功才成功，任一失败立即失败（快速失败），结果顺序与输入顺序一致；`allSettled` 等全部敲定，返回 `{status, value|reason}` 数组，适合批量任务互不影响；`any` 首个成功即成功，全失败抛 `AggregateError`；`race` 取首个敲定（成功或失败均可）。

### **13. `async/await` 的原理是什么？**

`async` 函数返回 Promise，内部基于 Generator 加自动执行器，`await` 把后续代码注册为该 Promise 的回调，恢复执行属于微任务。`await` 非 Promise 值也会让出一次执行权。异常用 `try/catch` 捕获被等待 Promise 的拒绝原因。

### **14. 串行与并发怎么写？**

`for` 循环里逐个 `await` 是串行（总耗时累加）；先 `map` 出 Promise 数组再 `Promise.all` 是并发（取决于最慢的一个）。限流用并发池，容错用 `allSettled` 或逐个 `try/catch`，取消用 `AbortController`。

### **15. 实现深拷贝要考虑哪些边界？**

循环引用（`WeakMap`）、`Symbol` 键、不可枚举属性、`Date/RegExp/Map/Set/TypedArray`、函数、原型链、`getter/setter`。`structuredClone` 是原生方案，支持循环引用与多数内置类型，但不支持函数、DOM 节点与原型；手写用 `Object.prototype.toString` 判类型 + 递归 + `WeakMap`。

### **16. 防抖和节流有什么区别，怎么实现？**

防抖把多次触发合并为最后一次（或首次立即执行后冷却），节流保证单位时间内最多执行一次。实现要点是保存定时器或上次时间戳，并提供 `cancel`/`flush`，组件卸载时必须取消，否则会内存泄漏或更新已销毁组件。场景：搜索联想用防抖，滚动加载、拖拽用节流。

### **17. 数组常用方法哪些会改变原数组？**

会改：`push/pop/shift/unshift/splice/sort/reverse/fill/copyWithin`；不改：`map/filter/reduce/concat/slice/join/flat/flatMap/find/findIndex/some/every/includes`。两个细节：`sort` 默认按字符串比较（数字排序必须传比较函数），`reduce` 不传初始值时以第一项为初始累积值。

### **18. 事件委托的原理与限制？**

利用冒泡把子元素事件统一绑在父容器上，用 `event.target` 判断来源（常配 `closest`）。优点：减少监听数量、动态节点自动生效、省内存。限制：不冒泡的事件（`focus`、`blur`、`mouseenter`）无法委托；`stopPropagation` 会中断；深层节点需要精确匹配；高频事件要注意性能。

### **19. ESM 与 CommonJS 有什么区别？**

ESM 编译期静态解析（可 tree-shaking）、导出是活绑定（值引用）、顶层 `this` 为 `undefined`、默认严格模式、支持顶层 `await` 与 `import()`；CJS 运行时 `require`、导出是值拷贝、循环依赖拿到未执行完的快照、`this` 指向 `module.exports`。`import` 会提升到模块顶部，`require` 按代码顺序执行。

### **20. 垃圾回收机制是什么，哪些情况会泄漏？**

V8 分代回收：新生代用复制算法（Scavenge），老生代用标记清除与标记整理，配合增量/并发标记减少停顿；可达性从根（全局、调用栈、活跃闭包）出发。泄漏场景：意外全局变量、闭包长期持有大对象、未清除的定时器与动画帧、未解绑的事件监听、游离 DOM、无上限缓存、组件卸载未清理的订阅与请求。

### **21. 为什么 `0.1 + 0.2 !== 0.3`？**

IEEE 754 双精度下 0.1 与 0.2 是无限循环二进制小数，存储时已舍入，相加产生误差。处理：金额用整数（分为单位）计算、最终统一舍入（`toFixed` 边缘值并非严格四舍五入）、或用 `decimal.js` 等高精度库。

### **22. 箭头函数和普通函数有什么区别？**

箭头函数无自己的 `this`、`arguments`、`prototype`，不能被 `new`、不能作为 Generator、不能用 `yield`，`this` 取外层且 `call/apply` 无效。因此不适合做构造函数、需要动态 `this` 的方法、以及需要 `arguments` 的场景。

## 2、难题

### **1. 微任务为什么会“饿死”渲染？**

微任务在每轮宏任务后会被**彻底清空**，包括清空过程中新产生的微任务。若一个微任务持续注册新的微任务（例如长 `Promise` 链或递归 `queueMicrotask`），事件循环会一直停在清微任务阶段，无法进入渲染，表现为页面卡住、交互无响应。所以重计算应切片并用宏任务（`setTimeout`、`MessageChannel`、`scheduler.postTask`）让出主线程。

### **2. `resolve` 一个 thenable 为什么要多一个 tick？**

`resolve` 收到对象时会读取其 `then` 属性，若为函数则进入“Promise 决议过程”，需要把 `then` 的调用排入微任务队列，因此状态敲定被推迟一个周期。这解释了输出题里“为什么 `resolve(new Promise(...))` 的结果比预期晚一轮”。

### **3. 循环变量闭包的三种写法为什么只有 `let` 有效？**

`var` 在函数作用域只有一个绑定，循环结束后所有回调读到同一个最终值；`let` 在每次迭代创建新绑定，各回调各持一份；不用 `let` 时可以用 IIFE 捕获当次值，或用 `bind`/额外参数把值传进去。这是“绑定作用域 vs 值捕获”的经典考点。

### **4. `for...in`、`for...of`、`Object.keys` 有什么区别？**

`for...in` 遍历**可枚举属性名**，会沿原型链向上（需配 `hasOwnProperty` 过滤），不适合数组（会把自定义属性也遍历）；`for...of` 遍历**可迭代对象的值**（数组、字符串、Map、Set、Generator），可被 `break` 中断；`Object.keys` 只返回自身可枚举字符串键。属性顺序规则：整数键按数值升序，字符串键按插入顺序，`Symbol` 需要 `Reflect.ownKeys` 才拿得到。

### **5. ESM 的循环依赖为什么能工作，CJS 为什么容易出错？**

ESM 的导入导出是活绑定，模块在解析阶段就建立引用关系，执行时先提升函数声明，未初始化的变量为 `undefined`（TDZ 之外的引用可能拿到 `undefined` 但绑定有效），因此只要不在初始化阶段立即使用就能正常工作。CJS 在运行时同步执行，循环依赖时后执行的模块拿到的是前一个模块**尚未赋值完成**的 `exports` 快照，容易拿到空对象。

### **6. Proxy 相比 `Object.defineProperty` 强在哪？**

Proxy 能拦截新增与删除属性、`in`/`has`、`ownKeys`、数组索引与 `length`、以及 `Map/Set` 的方法调用；`defineProperty` 只能拦截已存在的属性，必须初始化时递归遍历（Vue 2 的成本来源）。Proxy 不能代理原始值、对内置集合的内部槽位要绑定 `this`、且性能低于直接访问；代价是**无法 polyfill**，所以 Vue 3 不支持 IE。

### **7. 手写 `bind` 要注意什么？**

四个要点：返回新函数而非立即执行、支持分两次传参（`bind` 时传一部分、调用时再传一部分）、保留原函数的 `this` 语义（`new` 调用时绑定的 `this` 应被忽略）、保留原型链（`new` 出的实例应继承原函数的 `prototype`）。实现上用一个中间函数 `fNOP` 承接原型，再用 `instanceof` 或 `this instanceof` 判断是否被 `new` 调用。

### **8. `WeakMap`、`WeakRef`、`FinalizationRegistry` 分别解决什么？**

`WeakMap/WeakSet` 的键是弱引用，给对象附加数据但不阻止其被回收，适合缓存、私有数据、DOM 与实例的关联（这也是 Vue 3 依赖表用 `WeakMap` 的原因）。`WeakRef` 允许弱持有对象并可能取不到，适合做可回收的缓存。`FinalizationRegistry` 在对象被回收后回调，但时机不确定，不能用来替代显式清理（例如必须主动 `clearTimeout`）。

# 四、Less

## 1、常见题

### **1. Less 是什么，和 Sass/SCSS、Stylus 有什么区别？**

Less 是 CSS 预处理器，用变量、嵌套、混入、运算、函数把 CSS 变成可组织、可复用的代码，编译后输出普通 CSS。与 SCSS 的差别主要在语法与能力：Less 用 `@` 定义变量（SCSS 用 `$`），没有 `@if/@each` 这类控制指令，靠**守卫（when）+ 递归**实现条件与循环；没有 `@use/@forward` 那样的模块系统；因为编译者是 JS（`less.js`），可以在浏览器里直接编译运行，这是它早期在 Node 工具链里普及的原因。项目里选谁通常取决于团队既有栈与生态（组件库主题定制、构建插件支持）。

### **2. Less 变量与 CSS 变量有什么区别？**

Less 变量 `@primary: #1890ff` 在**编译期**被替换成字面量，产物里不存在变量，因此不能运行时修改、不能做动态换肤；CSS 变量 `--primary: #1890ff` 是运行时值，可被 JS 读写、参与继承、支持切换主题与过渡。实践组合是“Less 变量管理尺寸与间距这类编译期常量，CSS 变量承载颜色主题”，编译期用 Less 变量生成 CSS 变量声明。

### **3. Less 变量的求值顺序和覆盖规则是什么？**

Less 变量是**惰性求值**，不要求先声明后使用，同一个作用域内**后定义的生效**，查找时从当前作用域逐级向上。这带来两个实际后果：一是可以在文件末尾集中定义变量覆盖前面所有引用（主题覆盖就是这么做的）；二是容易“改了没效果”——若在使用处之后还有一处同名赋值，最终取后者。排查方式是全局搜索同名变量并确认作用域层级。

### **4. Less 的 `&` 有哪几种用法？**

`&` 表示父选择器。常见四种：`:hover` 等伪类（`&:hover`）、拼接后缀（`&-primary` 生成 `.btn-primary`）、反向嵌套（`.parent &` 表示“我被 .parent 包含”）、重复父级（`&&`）。BEM 写法 `&__elem`、`&--mod` 都靠它实现。**注意**：`&` 拼出来的是**新选择器**，权重与父级一致，嵌套层级不会额外加权，但嵌套过深仍会让选择器变长。

### **5. Mixin 怎么定义和调用，带不带括号有什么区别？**

定义 `.clearfix() { ... }`（带括号）是纯混入，本身不输出 CSS；`.clearfix { ... }`（不带括号）既是类也会输出。调用 `.clearfix();` 或 `.clearfix;` 均可。带参数版本 `.btn(@color; @padding: 8px 12px) { ... }`，参数分隔符建议用分号（逗号在 `box-shadow` 这类值里会歧义）；`@arguments` 表示全部实参，`@rest...` 收集剩余参数。

### **6. Mixin 与 `:extend` 有什么区别？**

Mixin 是**复制声明**到当前选择器，产物里出现多份相同声明；`:extend` 是**合并选择器**，把当前选择器追加到被继承规则的选择器列表上，产物只有一份声明。因此大量重复样式用 `:extend` 体积更小，但要注意它会改变选择器结构、且无法继承带参数的混入。`:extend(.b all)` 会把 `.b` 的所有嵌套变体一并继承。判断标准：需要参数或需要独立作用域用 mixin，纯复用声明用 extend。

### **7. Less 的运算怎么用，除法为什么要注意？**

支持 `+ - * /` 与括号，单位会参与计算（`10px + 5px` 得 `15px`，单位不一致时以第一个为准）。**重点**：Less 4 默认数学模式为 `parens-division`，即不带括号的 `/` 被视为 CSS 分隔符（例如 `font: 16px/1.5` 不再做除法），要做除法必须写成 `(width / 2)` 或用 `./`。老项目从 Less 3 升级时“数值算错”基本都是这个原因。

### **8. `~"..."` 转义是干什么的？**

把引号里的内容原样输出，不让 Less 解析。三类场景：`calc()`（`width: ~"calc(100% - 20px)"`）、`url()` 中含特殊字符、被 Less 误判为运算或函数的 CSS 值（如 `filter`、`grid-template-areas`、旧式 `alpha(opacity=50)`）。另一种等价写法是 `e("...")`。反过来，若希望 `calc` 里参与变量计算，就**不要**转义，让 Less 先把变量替换掉再交给 CSS。

### **9. Less 有哪些常用内置函数？**

颜色：`lighten/darken`、`saturate/desaturate`、`fadein/fadeout/fade`、`spin`、`mix/tint/shade`。数值：`percentage`、`round/ceil/floor`、`unit`、`min/max`。字符串与列表：`escape`、`e`、`length`、`extract`、`range`、`each`。判断类：`iscolor`、`isnumber`、`isruleset`（配合守卫）。做主题色板时最常用 `lighten/darken/mix` 批量生成梯度。

### **10. `@import` 有哪些选项，和 CSS 的 `@import` 有什么区别？**

Less 的 `@import` 在编译期**内联**文件内容，可选 `(reference)` 只引入不输出（配合 `:extend` 按需取样式）、`(inline)` 原样嵌入不处理、`(css)` 保留为 CSS 原生导入、`(optional)` 文件缺失不报错、`(once)` 默认只导入一次、`(multiple)` 允许重复导入。CSS 的 `@import` 是运行时请求、串行加载、性能差，工程上应避免。

### **11. 条件与循环怎么写？**

条件用守卫：`.mixin(@x) when (@x > 0) { ... }`，支持 `and`、`or`、`not`，以及 `iscolor()` 这类类型判断；搭配 `default()` 处理兜底分支。循环用**递归 + 守卫**实现：

```
.generate(@n) when (@n > 0) {
  .col-@{n} { width: (@n / 12 * 100%); }
  .generate(@n - 1);
}
.generate(12);
```

Less 3.7+ 也可以用 `each(@list, .mixin)` 遍历列表，可读性更好。

### **12. 命名空间怎么用？**

把一组混入装在 `#ns()` 里（带括号就不会输出），通过 `#ns > .mixin()` 或 `#ns.mixin()` 调用；也可以写成 `#ns { .mixin() {} }` 但会被输出。命名空间的价值是把“工具方法”与“实际样式”隔开，避免工具类污染产物，也便于按模块组织。

### **13. 注释有什么区别？**

`//` 单行注释在编译后**被删除**，适合写给人看的说明；`/* */` 块注释**保留在产物中**，只在压缩模式下被移除，适合需要保留版权声明或给调试用的标记。团队规范一般要求业务注释用 `//`，版权与许可证用 `/* */`。

### **14. 在 Vite 里怎么配置 Less，怎么注入全局变量？**

安装 `less` 后，在 `vite.config` 的 `css.preprocessorOptions.less` 里配置：`additionalData` 用来自动注入变量文件（`@import "@/styles/variables.less";`），`javascriptEnabled: true` 支持内联 JS（组件库主题包常用），`modifyVars` 用于编译期换主题（配合 Ant Design 这类库）。Webpack 侧对应 `less-loader` 的 `additionalData` 与 `globalVars`，`globalVars` 的值可以是 JS 字符串，便于读取环境变量做主题。

### **15. 用 Less 做换肤有哪几种方式？**

两种：编译期（`modifyVars` 或变量覆盖，产出一套新 CSS，切换要重新加载样式文件，适合多套固定主题）、运行时（Less 变量生成 CSS 变量，切换时只改 `document.documentElement` 上的 CSS 变量，零重新编译，适合深色模式与实时预览）。工程上常用“Less 管编译期常量 + CSS 变量管主题色”的混合方案。

### **16. Less 的常见坑有哪些？**

嵌套过深导致选择器过长、权重过高、后续只能靠 `!important` 覆盖；混入滥用导致产物重复声明、体积膨胀；变量后定义覆盖前面（以为没生效）；Less 4 的除法需括号；`calc` 未转义被 Less 提前计算成固定值；`@import` 顺序影响变量最终取值；把 Less 变量误当 CSS 变量写进 `var()`（`var(--x)` 里不能放 Less 变量）。

## 2、难题

### **1. 为什么“在文件末尾覆盖变量”能改掉前面所有用法？**

因为 Less 变量是惰性求值且在作用域内后定义优先：解析时先收集所有声明，再在**使用点**所在的“最终作用域状态”上求值，而不是按书写顺序即时求值。所以把主题变量集中在文件末尾（或单独文件并在最后 `@import`），就能一处覆盖全量引用。反过来这也是坑：组件内部若在文件末尾重复赋值同名变量，会意外影响该文件内所有引用。

### **2. `@import (reference)` 配合 `:extend` 是怎么省体积的？**

`(reference)` 让被导入文件“只解析不输出”，里面的规则不会出现在产物中；当你在自己的选择器里 `:extend(.their-rule)` 时，Less 会把你的选择器合并到那条原本不输出的规则上，从而**只输出真正用到的那部分样式**。适合引入大型组件库或公共样式后按需取用，代价是产物结构不够直观、调试时不容易对应源码。

### **3. `:extend` 的 `all` 关键字会带来什么问题？**

`:extend(.btn all)` 会把 `.btn` 及其所有嵌套变体（`.btn:hover`、`.btn.active`、`.wrapper .btn`）一并继承，覆盖更全但**选择器数量会成倍增长**，产物可能比 mixin 更大，且容易出现意料之外的样式串味。使用时应对准具体规则，而不是对大块组件做 `all`。

### **4. 守卫（when）递归与 `each` 循环怎么选？**

守卫递归兼容性最好、可表达“递减到 0”这类条件终止，但每个循环项都会产生一次编译调用，数量大（如生成 100 档间距）时编译耗时明显；`each` 遍历列表语义更清晰、性能更好，但需要 Less 3.7 以上。实践建议：工具类生成控制规模（几十档以内）、优先 `each`，并避免在循环里做复杂颜色函数运算。

### **5. 为什么 `width: calc(100% - @gap)` 有时算错？**

Less 会在编译期尝试对 `calc` 内的表达式求值，把 `@gap` 替换后若整个表达式可算（如 `100% - 20px` 单位混合），可能被简化为一个值或产生不合法的 CSS。正确做法是 `width: calc(100% - @gap)` 保留变量替换但让 CSS 负责运算（多数版本可正确输出），或在需要完全原样输出时用 `~"calc(100% - 20px)"`；反过来若想用 Less 算好再输出，就写成 `width: (100% - @gap)`（不带 `calc`）。判断标准是“这个运算该由编译器做还是浏览器做”。

### **6. 深层嵌套为什么会拖慢编译并让样式难以维护？**

每个嵌套层级都会展开成一条更长的选择器，嵌套 n 层且每层多个选择器时，产物的规则数近似指数增长；同时选择器变长会增加匹配成本，权重升高后覆写只能加 `!important`。更隐蔽的问题是“样式串味”——上层模块改变结构后，深层嵌套的样式会意外命中其他节点。规范做法是嵌套不超过两层、用 `&` 明确关系、跨模块的样式不用后代选择器。

### **7. Less 与 CSS Modules 一起用要注意什么？**

Less 负责能力（变量、混入、运算），CSS Modules 负责作用域（类名哈希）。要点：只对局部类做哈希，公共类用 `:global(.ant-btn)`；`composes` 只能引用同文件或导入的类，不能引用动态值；`:extend` 在 CSS Modules 下行为受限（跨文件继承不生效）；主题变量通过 `:export` 或 CSS 变量导出给 JS 使用；命名保持 `camelCase` 以免 `styles['kebab-case']` 写法踩坑。

# 五、TS

## 1、常见题

### **1. TypeScript 的类型系统有什么特点？**

三点：一是**结构类型**，只看形状是否匹配、不看声明来源（同形状的对象可互相赋值），与 Java 的标称类型不同；二是**编译期检查 + 类型擦除**，类型在产物中不存在，运行时没有任何类型信息，因此“运行时校验”必须另做（如 zod）；三是**渐进式**，`any` 与 `// @ts-expect-error` 可以把检查降到局部，便于老项目迁移。

### **2. `interface` 和 `type` 有什么区别，怎么选？**

`interface` 描述对象形状、支持**声明合并**（同名自动合并，适合扩展第三方库类型）与 `extends`；`type` 可为任意类型起别名，支持联合、交叉、条件类型、映射类型与元组，但不能重复声明。约定：对象结构用 `interface`，需要联合/条件/映射运算时用 `type`。

### **3. `any`、`unknown`、`never`、`void` 有什么区别？**

`any` 关闭检查、可读写任意属性、会污染下游推断；`unknown` 是安全版 `any`，任何值都可赋给它，但使用前必须收窄，适合 `catch` 的 `error` 与外部输入；`never` 表示空集（不可能出现的值、永不返回的函数），可用于穷尽性检查；`void` 表示函数没有返回值（实际返回 `undefined`），常用于“返回值不被使用”的回调签名。

### **4. 泛型是什么，为什么要用它？**

让类型随输入推导，而不是靠断言或 `any`。三个要素：约束 `T extends Shape`、默认值 `T = string`、以及推导来源（参数、返回值、构造器）。判断“用得好不好”的标准是调用处能否**不写类型参数**就得到正确类型；如果函数内部需要访问属性却没有约束，就是没设计好。

### **5. 常用工具类型有哪些？**

`Partial/Required/Readonly`（改修饰符）、`Pick/Omit`（取/去键）、`Record`（构造索引签名）、`Exclude/Extract/NonNullable`（过滤联合）、`ReturnType/Parameters`（提函数签名）、`InstanceType`、`Awaited`（递归展开 Promise）、`ConstructorParameters`。它们几乎都是映射类型与条件类型的组合，能手写就是理解到位的证据。

### **6. `keyof`、`typeof`、索引访问类型分别干什么？**

`keyof T` 取键的联合（`'a' | 'b'`）；`typeof x` 取变量或值的类型（常配合 `as const` 从常量推导字面量）；`T['a']` 或 `T[keyof T]` 取属性类型。三者常组合成“从已有对象推导配置类型”的写法，避免重复定义。

### **7. 条件类型和 `infer` 怎么用？**

`T extends U ? X : Y` 表达类型层分支，`infer` 只在 `extends` 子句中声明待推断变量。典型：`type RT<T> = T extends (...a: any[]) => infer R ? R : never`（取返回值）、`type Aw<T> = T extends Promise<infer V> ? Aw<V> : T`（递归展开）。注意 `infer` 出现在参数位置（逆变位）时，推断结果是交叉而非联合。

### **8. 映射类型是什么？**

`{ [K in keyof T]: F<T[K]> }` 遍历键生成新类型，可在 `in` 后用 `as` 重映射键名、用 `+?`/`-?` 与 `+readonly`/`-readonly` 增删修饰符。它是 `Partial`、`Readonly`、`Pick` 的实现基础，也是“批量改造对象类型”的主力工具。

### **9. 联合类型与交叉类型的实际差异？**

联合 `A | B` 表示“或”，只能访问两者共有的属性；交叉 `A & B` 表示“并”，可访问全部属性。基本类型交叉会得到 `never`（如 `string & number`），对象交叉是属性合并（同键类型冲突时也变 `never`）。常见用法：`Props & { children?: ReactNode }` 做类型叠加。

### **10. 类型收窄有哪些手段？**

`typeof`（基础类型）、`instanceof`（类实例）、`in`（属性存在）、字面量判别字段（可辨识联合，推荐建模方式）、真值判断与相等判断。自定义守卫：`function isX(v: unknown): v is X`；断言函数：`function assertX(v: unknown): asserts v is X`（失败时抛错）。守卫只影响编译期，运行时安全性取决于实现是否正确。

### **11. `?.`、`??`、`!` 分别是什么？**

`?.` 可选链（中间为 `null/undefined` 时短路返回 `undefined`）；`??` 空值合并（只在 `null/undefined` 时取右侧，不像 `||` 会被 `0`、`''` 误判）；`!` 非空断言（告诉编译器“一定存在”，不做运行时检查，滥用会掩盖真实空值 bug）。三者常一起出现在接口数据处理里。

### **12. `as`、`as const`、`satisfies` 有什么区别？**

`as` 是类型断言，强行告诉编译器“当成这个类型”（不校验、可能掩盖错误）；`as const` 让字面量保持最窄类型并加 `readonly`（用于常量表、路由表）；`satisfies` 是**校验同时保留推断**，既能对配置对象做形状检查，又不放宽键的精确类型。

### **13. 函数重载怎么写，注意什么？**

写多个重载签名（只有声明）加一个实现签名。要点：实现签名**对调用方不可见**，重载签名必须覆盖所有调用形态；重载过多时可用条件类型或联合参数替代（更易维护）。适合“入参类型不同、返回类型随之不同”的工具函数，不适合堆砌不同业务逻辑。

### **14. 声明文件与模块增强怎么写？**

为无类型库补声明：建 `d.ts` 并在 `include` 中纳入，用 `declare module 'pkg'` 声明形状；扩展已有模块：`declare module 'pkg' { interface X { extra: string } }`；全局注入：`declare global { interface Window { __CONFIG: Config } }`。要求是声明与实现同步，最好加类型测试（`tsd`/`expect-type`）防漂移。

### **15. `tsconfig` 里 `strict` 包含哪些？**

`noImplicitAny`、`strictNullChecks`、`strictFunctionTypes`、`strictBindCallApply`、`strictPropertyInitialization`、`alwaysStrict`、`useUnknownInCatchVariables`、`noImplicitThis`。其中工作量最大的是 `strictNullChecks`（可选值与返回值都要显式处理），其次是 `strictFunctionTypes`（影响回调参数的赋值检查）。另有 `noUncheckedIndexedAccess` 不在 `strict` 内，但强烈建议对数据边界敏感的项目开启。

### **16. 类型擦除有什么实际后果？**

类型、接口、类型断言在编译后全部消失，所以不能用类型做运行时判断（`typeof` 只能判基础类型，不能判 `interface`）；`as` 不会转换数据；泛型不能用于 `new` 之外的运行时逻辑；`instanceof` 只能对真实存在（有运行时值）的类使用。

### **17. 枚举（enum）有什么问题，替代方案是什么？**

数字枚举会产生反向映射、字符串枚举无反向映射；`const enum` 会被内联，但在 `isolatedModules`（Babel/esbuild 场景）下不能跨模块使用，容易“本地编译通过、构建失败”。现代实践多用“字面量联合 + `as const` 对象”替代：

```
const Status = { Idle: 'idle', Loading: 'loading' } as const;
type Status = typeof Status[keyof typeof Status];
```

### **18. Vue 3 项目里 TS 有哪些关键写法？**

`defineProps<Props>()` 与 `defineEmits<{ change: [id: number] }>()` 的类型推导；模板引用 `ref<HTMLInputElement | null>(null)`；`provide/inject` 用 `InjectionKey<T>` 保证类型；全局属性用模块增强；`defineModel<T>()` 声明双向绑定类型。要点是“props 用泛型而不是运行时的对象声明”，否则拿不到类型。

### **19. React 项目里 TS 的关键写法？**

事件类型用内置泛型（`ChangeEvent<HTMLInputElement>`、`MouseEvent`），避免手写 `any`；`useState` 初始为 `null` 时显式声明联合类型；`children` 用 `ReactNode`；泛型组件写成 `function List<T>(props: Props<T>)`；`useRef<HTMLDivElement>(null)`。常见坑是用 `forwardRef` 时忘了传泛型导致 `ref` 类型丢失。

### **20. 怎么给一个值加上“不可能为 null”的类型保障？**

不要用 `!`，而是用控制流收窄：`if (x == null) return;` 之后编译器自动排除 `null`；或写断言函数 `assertDefined<T>(v: T | null | undefined): asserts v is T`，在入口统一校验。前者是纯类型层面的安全，后者带运行时检查，二者比非空断言可靠得多。

## 2、难题

### **1. 什么是分布式条件类型，怎么阻止它分发？**

当条件类型作用于**裸类型参数**且传入联合时，会按成员逐个求值再合并结果（`type E<T> = T extends string ? 1 : 2`，传入 `'a' | 1` 得 `1 | 2`）。阻止分发用元组包裹：`[T] extends [U] ? ...`，此时整体比较、不再拆成员。`Exclude`、`NonNullable` 都依赖分发特性，而“判断两个联合是否完全相同”必须阻止分发。

### **2. `infer` 在参数位置为什么得到交叉类型？**

`infer` 处于逆变位置（函数参数）时，多个候选类型会被推断为**交叉**，这正是 `UnionToIntersection` 的实现原理：

```
type U2I<T> = (T extends any ? (x: T) => void : never) extends (x: infer I) => void ? I : never;
```

而处于协变位置（返回值、属性）时得到联合。理解这一点能解释很多“类型体操结果与直觉不符”的问题。

### **3. 协变、逆变与 `strictFunctionTypes` 有什么关系？**

对象属性与返回值是协变（子类型可赋给父类型），函数参数是逆变（参数类型更宽的函数才能赋值给参数更窄的位置）。开启 `strictFunctionTypes` 后，函数类型属性按逆变检查；但**方法的参数仍保持双变**（bivariant），这是为兼容历史行为留的口子。实践含义：把回调声明为属性签名（`onChange: (v: string) => void`）比声明为方法签名检查更严格。

### **4. 手写 `DeepPartial` 需要注意什么？**

要限定递归边界，否则对含循环引用的类型会“类型实例化过深”：

```
type DeepPartial<T> = T extends object
  ? { [K in keyof T]?: DeepPartial<T[K]> }
  : T;
```

要点：`extends object` 排除基础类型；遇到数组、函数、`Date` 等内置类型要单独分支（否则会把 `Date` 也变成可选属性的对象）；递归深度超过编译器限制（约 50 层）会报错，需要用“分层递归”或显式深度参数控制。

### **5. `satisfies` 解决了 `as` 与类型注解都解决不了的问题？**

类型注解会把对象放宽成声明类型，丢失具体键的窄类型（键名补全、字面量类型都没了）；`as` 只断言不校验。`satisfies` 二者兼得：既做形状校验（拼错键会报错），又保留推断结果（`obj.home` 仍是 `'/'` 字面量类型）。典型场景：路由表、主题 token、i18n 字典。

### **6. TS 5 的标准装饰器与 `experimentalDecorators` 有什么区别？**

标准装饰器（Stage 3）签名是 `(value, context)`，`context` 提供 `kind`、`name`、`addInitializer`，可用于类、方法、字段、访问器与 `accessor` 关键字；`experimentalDecorators` 是旧的 `(target, key, descriptor)` 风格，需要配合 `emitDecoratorMetadata` 才能做依赖注入（NestJS、Angular 依赖这套）。两者不能混用，`experimentalDecorators: true` 时标准装饰器不生效。

### **7. 对象字面量的“多余属性检查”为什么能绕过？**

TS 对**新鲜（fresh）**对象字面量做多余属性检查：直接赋给带类型的变量或传参时报错；但若先赋给一个中间变量（类型被拓宽为字面量的形状），再传给目标类型，检查就失效，因为此时不再是“新鲜字面量”。这是“为什么 `const a = {x:1, y:2}; const b: A = a;` 不报错”的原因。工程含义：不要用中间变量绕过检查，那会掩盖真实的结构不匹配。

### **8. 类型安全与运行时校验怎么配合才不白做？**

TS 只能保证“代码内部的类型自洽”，无法保证外部数据（接口响应、`localStorage`、URL 参数）符合声明。可靠做法是在边界处做运行时校验：接口层用 zod/valibot 定义 schema 并推导类型（`z.infer`），校验失败走统一错误处理；这样声明类型与运行时校验来自同一份定义，避免“两套定义漂移”。只用 `as ApiResponse` 断言是典型的假安全。
